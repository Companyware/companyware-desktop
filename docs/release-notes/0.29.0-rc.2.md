# Companyware Desktop 0.29.0-rc.2

Status: **GitHub pre-release candidate**

This candidate contains Companyware Desktop only. Companyware Web is released
independently from its Symfony repository and has separate evidence.

## Changes since 0.29.0-rc.1 preparation

- Add the standalone Java-8 plugin starter with a version-bound public SDK,
  descriptor, tests, documentation and deterministic `.cwp` packaging.
- Complete the Desktop sidebar interaction follow-ups so direct, grouped and
  account navigation share one active target without restoring stale selections.
- Keep the release workflow version-independent and require the runtime-visible
  version to match the Maven artifact version.
- Make Hibernate mappings and built-in plugin discovery work from the executable
  Spring Boot JAR, and add a one-click Windows release build that also creates a
  Launch4j `Companyware.exe`.

## Compatibility and limitations

- Requires a 64-bit Java 8 JRE or newer compatible runtime; building requires a
  JDK with `javac` and a matching `JAVA_HOME`.
- Existing Maven coordinates, Java packages, plugin IDs, public API 1.x contracts,
  Derby schema identifiers and the `Companyware.jar` launcher name remain stable.
- Plugins execute as trusted in-process code. Public third-party distribution is
  not approved until publisher signatures and the remaining Store-neutral trust
  gates are complete.
- The Launch4j EXE requires Java 8 or newer. This candidate does not bundle a
  private Java runtime or installer and does not imply a Companyware Web release.

## Downloads and source

- End users download `companyware-desktop-0.29.0-rc.2.zip`, verify the adjacent
  SHA-256 file, unpack the archive and start `Companyware.exe`. The archive also
  contains the executable `Companyware.jar` and `start-companyware.cmd`; no
  source build is required.
- Developers use the immutable `v0.29.0-rc.2` source tag, build with a 64-bit
  JDK 8 and the checked-in Maven Wrapper, and follow `docs/developer-guide.md`.
- No MSI/setup installer or bundled Java runtime is part of this candidate. The
  Launch4j EXE and direct JAR path require their own Windows start/stop evidence.

## Publication gate

The authoritative commit and artifact hashes come from `release-evidence.json`
attached to the GitHub pre-release. Publication requires the full framework,
two-build clean-clone, packaged Windows start/stop, dependency and external
GitHub security gates in `docs/github-publication-checklist.md` to pass on the
selected commit.
